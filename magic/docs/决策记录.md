## 2026-09-21 · 更正：槽位替换不靠 priority，且注册必须包 `ctx.slots.inject`
本仓 `AGENTS.md` §5.4 与 `底座边界.md` §2.1 原先写"用 `ctx.slots.register` 复用同一 cell +
priority 影子"，与源码不符：外部注册**不许传 `priority`**，框架自动给一个低于全部出厂项的值，
所以在 `single`/`keyed` 单元里注册者即赢家，在 `list` 里只能追加（复用同 id 才替换同 cell）
（`packages/extensions/cordis-client-runner/src/client/slot-catalog.ts:71`）；且槽位只在声明者
挂载时存在，裸注册进未声明的槽直接抛，必须包 `ctx.slots.inject(name, () => register(...))`
（同文件 :70）。
**为什么**：界面改造第③层的存活前提写错了方向 —— 以为要靠调优先级竞争，实际是"传了就违规、
不传就已经赢"。
**影响到哪**：两处条文已按源码改写；老仓 `AGENTS.md` 修改规则第 6 条有同一个错，那是只读参考仓，
不改，以本仓为准。

## 2026-09-21 · 更正一条风险定级：吃旧历史不是"不可逆改写"
原先记"0.1.6 可能改写会话文件，属不可逆"。源码不支持这个说法：`SESSION_FORMAT_VERSION = 3`
（`packages/core/session/src/types.ts:88`）在 0.1.6 不升，代文件不可变、恢复旧会话是**前滚出新代**
而非覆盖旧代（`packages/session/session-persistence-jsonl/src/generation.ts:5-6`、`format.ts:27`）。
**但**起 3099 那台实例会往它自己的 home（`D:\Harmess\Magic\.magic-dsh-live`）追加写，所以
"老仓只读"在起实例时并不成立 —— 碰之前先冷复制那份 home，这是唯一仍需的防护。
**影响到哪**：待裁定第 3 条的定级从"不可逆"降为"会派生新代"；冷备份照做。
