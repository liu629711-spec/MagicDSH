# 决策记录

为什么单独一份：裁定散在 patch 注释、PRD、AGENTS 和对话里，隔一周就没人知道哪条还算数。
每条格式固定：**日期 · 裁定 · 为什么 · 影响到哪**。

## 2026-09-13 · 第三方能力以 vendored 整包接入，浏览器基线定 `dsh-builtin-browser`
引入 sidenote / prompt-optimizer / harness-zh / better-sidebar / univer；同日摘除自研
`magic-browser` v1 与 `dsh-ego-browser`。
**为什么**：两套 `browser_*` 工具并存会让模型随机选择、面板互相顶掉（实测到的混淆现场）。
**影响到哪**：老仓 `plugins/dsh-*` 六包。**这条今天被部分推翻，见 2026-09-21 的收口条目。**

## 2026-09-15 · 工程模式从产品移除
删 `magic-engineering` 插件与 PRD-03，CEO 模式是唯一协作组织方式。
**为什么**：不做长期工程组织。
**影响到哪**：老仓 `plugins/magic-engineering` 是残留尸体，待删。

## 2026-09-20 · 界面动作按钮一律单图标 + hover tooltip；布局要紧致密集
轨迹视图按此改（展开/收起合并成一枚切换胶囊）。
**为什么**：文字标签按钮太占、双状态该合成一个按钮。
**影响到哪**：后续所有界面改造。同时定下一条验收纪律：**图标字形是否真渲染必须看渲染结果，
`textContent` 测不出来**（`fold_less` 那种非法字形名当时渲染成字面量）。

## 2026-09-21 · 停止自建客户端，改 fork DSH 底座并直接改它的官方外壳
`apps/magic-desktop` 停止并从 main 移除，tag `archive/magic-desktop-2026-09-21`。
**为什么**：自建壳要手抄底座输出，而底座每版本动几千个代码文件，这条路不收敛。
**影响到哪**：路线本身。底座 fork = MagicDSH，分支 `magic/main`，基点 tag
`dsh-v0.1.6-alpha.2`。

## 2026-09-21 · 不再跟随上游更新
"要不停 rebase"这条反对理由作废；fork 是自己的产品本体。
**影响到哪**：`底座边界.md` 第 2 节第 3 条 —— 因此登记表成了唯一真相来源。

## 2026-09-21 · 体验基准改为"我们自己实例实际渲染出来的样子"
官方裸壳形态不作基准；被我们改过、被插件接管过的任何形态，一律以本机实测为准。
**影响到哪**：AGENTS 第一原则第 8 条。

## 2026-09-21 · 3099 从"运行基准"降为"能力参考基线"；其缺陷清单作废
自建壳已归档，那份能力差文档的"客户端"列（含 CEO 画布位置错乱）随之作废 ——
那是已废弃产品的缺陷，不是待办。
**影响到哪**：`docs/02-实现/10-客户端与3099能力差.md` 降级重做成 `对标-3099基线.md`；
"需求来自 3099，实现优先来自底座"成为对表判据。

旧结论标为**待重核**，不再当定论使用。
