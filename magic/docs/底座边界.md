# 底座边界

三份东西合成一份：**我们把 fork 改了哪几处**、**哪些绝对不许碰**、**改完怎么让它生效**。
这份文档的存在理由只有一条：fork 面积 = 日后成本，所以每一处改动都必须可数、可回退。

规则：改 `magic/` 以外任何文件，源码里留 `Magic fork delta:` 注释，且在这里加一行。
回退方式统一是 `git checkout <tag dsh-v0.1.6-alpha.2> -- <文件>` 后重审。

## 2. 禁改清单

1. **槽位契约不许动**：槽名、owner props、cardinality。变了会一起崩的是挂载在 `ctx.slots`
   上的全部插件（我们现在 8 个自研 + 官方 47 个 `packages/client/ui-*`；同目录另有 8 个非呈现层
   基建包 `connection file-upload hmr locale modules resources store web`）。
   要换某个官方部件的表现，用 `ctx.slots.register` 复用同一 cell，但**不要自己传 `priority`**：
   客户端门面对手里所有非 `chain` 槽**无条件覆盖** `options.priority`
   （`packages/extensions/cordis-client-runner/src/client/guard.ts:128-131`），值取自页面内计数器
   `--nextPriority`（同包 `runtime.ts:183,424`），首个注册者得 −1，低于全部出厂项（默认 0），
   最低者渲染（`packages/client/ui-slots/src/index.ts:1135-1141`）—— 所以 `single`/`keyed` 格里
   注册者即赢家，`list` 只能追加、复用同 id 才替换同格，`chain` 走自己的选举不受此影响。
   老仓 `plugins/magic-ceo-ui/src/client/register.ts:470` 传的 `priority: -10` 会被这层覆盖掉，
   **迁入前必须实测确认对 `turn-process` 的影子仍然成立**。
   每条注册还要包在 `ctx.slots.inject(name, () => ctx.slots.register(...))` 里 —— 槽位只在声明者
   挂载时存在，裸注册进未声明的槽直接抛（`slot-catalog.ts:70`）。权威清单由
   `scripts/gen-client-catalog.ts` 生成；活树上的实际占用可用 `cordis_inspect what:"client"` 读回。
2. **挂产品插件不要改 `apps/desktop` 源码**。`apps/desktop-host/src/index.ts:23` 显式传
   `patchFiles: []`（桌面端不吃 `--patch`），但有两条不改源码的收口路：写该 profile 目录的
   `cordis.patch.yml`（`packages/boot/app-boot/src/profile.ts:897-900` 会读），或写
   `$DSH_HOME/cordis.patch.yml`（`profile-context.ts:68`）；也可以在 profile 里声明产品 bundle
   （`dsh.bundle.patch` 路线）。桌面端到端还没跑通过。
3. **不追上游更新**。已经裁定不再使用上游后续版本内容，所以不存在"要保持可 rebase"的约束；
   但也正因如此，第 1 节的登记表是唯一的真相来源——不登记就等于没人知道我们动了壳。

## 3. 构建与生效（踩过的坑都在这里）

- **两半分属两个 pass**：`lib/index.js` 出自 Host pass（`pnpm run build:lib:host`），
  `lib/client.js` 出自 Client pass（`build:lib:client` 或该包 `pnpm run bundle`）。
  只跑一面就漏另一半。今天漏跑 host 面的现场：挂载点 `failed to import`，
  而依赖它的 memory/consult/ceo 一起变成 `pending (waiting for service: magicWorkMode)`。
- **改任何底座包必须跑该包 `pnpm run bundle`（tsdown）才生效**。`apps/web` 的 `vite build`
  全绿是静默空跑——它不含动态客户端包。
- `dev:web` 是 watch 回路，但**要求先完整 build 一次**，且不得与 build 并发。
- 客户端包产物 `lib/` 不入库（`.gitignore` 第 7 行），所以从源码挂载前要先把 monorepo 建完。
- 构建进行中不要 `ls dist` 判断成败：vite 会先清空 outDir，中途看是空的（今天误判过一次）。

## 4. 挂载机制事实（`--patch`）

- `--patch` **可重复**，按 argv 顺序合成 overlays（`apps/cli/src/args.ts:66` collect +
  `apps/cli/src/profile-boot.ts:213` flatMap）。`dsh web` 等价 `dsh --profile web`。
- insert 的 `name` **只有以 `./` 或 `../` 开头**才按 patch 文件所在目录解析为路径，
  否则被当裸包名（`packages/boot/app-boot/src/index.ts:320-330`）。
- 一个 loader entry 导入失败会怎样：**待重核**。今天实测到的是"该条 failed to import +
  依赖它的服务链 pending，服务器照常起来"；早先在 rc.2 探测期记过"abort 整棵插件树"。
  两种失败种类可能不同（解析失败 vs 求值抛错），不要拿旧结论当定论。
- 桌面端 profile 会清空 `--patch`（`apps/desktop-host/src/index.ts:23` `patchFiles: []`），
  所以"web 上挂上了"不等于"桌面上挂上了"。
